# 長期認知基盤ロードマップ

Sentinel は短期の売買判断を自動化するための仕組みではなく、構造、証拠、時間コスト、認知資源を分離して観測するための長期認知コックピットとして扱う。

## 基本方針

- Gate と実行層は最後まで独立させる。
- 新しい観測レイヤーは原則として表示、監査、週次校准に限定する。
- 個人の実口座、実保有、主観的確信はシステム内部へ混ぜない。
- システムは世界を観測するが、人生や売買を代行しない。

## 全体フェーズ

### Phase 1: Evidence Quality Model

目的は、証拠の数と証拠の質を分離すること。

実装項目:

- `OfficialIR` を高品質証拠として扱う。
- `Manual` を人工確認または二次証拠として扱う。
- `PriceAction` を価格確認として扱う。
- `NewsMedia` を低品質またはノイズ寄り証拠として扱う。
- Telegram / Markdown に証拠品質サマリーを表示する。
- Gate、Engine、Execution には接続しない。

受け入れ条件:

- `502件の記録` がそのまま `502件の高品質証拠` と誤読されない。
- 高品質、人工/二次、価格確認、メディアノイズを区別できる。
- 三言語の表示契約テストが存在する。

### Phase 2: Asset Thesis Registry

目的は、銘柄ごとに「なぜ観測するのか」を構造化すること。

実装項目:

- 設定ファイルに銘柄別 thesis を定義する。
- thesis は取引判断ではなく観測命題として扱う。
- 例: `NVDA` は AI インフラ需要、`GOOG` は AI 収益化、`TSLA` は Physical AI、`PLTR` は企業 AI 組織化。
- 週次または日次の認知レポートで thesis と現在の証拠を対応づける。

受け入れ条件:

- 良い会社と良い観測対象を分離して説明できる。
- thesis が Gate に流入しない。

### Phase 3: Holding Efficiency / Time Cost Model

目的は、長期ロジックを否定せずに、価格先取りと時間コストを表現すること。

実装項目:

- 過熱、周期位置、証拠品質を使い、持有效率を表示する。
- `TIME_COST_RISING` は看空ではなく、待機価値が上がっている状態として扱う。
- 超配分時の露出低下は、長期保有を改善するための選択肢として説明する。

受け入れ条件:

- `GOOG` のような好会社でも、価格先取りと時間コストを説明できる。
- 実保有を読まず、仮想的なリスク処置として表示する。

### Phase 4: Weekly Calibration Report

目的は、週次でシステムと体感の距離を校准すること。

実装項目:

- Evidence Quality の変化を週次で集計する。
- Research Attention の変化を週次で集計する。
- Holding Efficiency の変化を週次で集計する。
- `市場理解は近づいたか`、`どこがズレたか` を固定フォーマットで出す。

受け入れ条件:

- 周報だけで変化が読める。
- 新しい売買シグナルを生成しない。

### Phase 5: Signal Attribution

目的は、システム状態の変化が何に由来したかを分解すること。

分類:

- 価格由来。
- 証拠由来。
- リスク由来。
- 周期位置由来。
- ノイズ由来。

受け入れ条件:

- `なぜ出力が変わったか` を監査できる。
- ノイズによる変化を後から識別できる。

## 禁止事項

- Evidence Quality を売買判断へ直結しない。
- Asset Thesis を個人ポジション管理へ混ぜない。
- Holding Efficiency を自動清算指示へ変換しない。
- Weekly Calibration を採点ゲームにしない。
- Signal Attribution を未来予測に使わない。

## 現在の実装開始点

本 Work Item では Phase 1 の最小実装として、表示層に Evidence Quality Summary を追加する。これは長期基盤の最初の地ならしであり、意思決定層への接続は行わない。
