# Moomoo 統合チェックリスト

## 1. 目的

このチェックリストは、Sentinel を moomoo/OpenD に接続する際のエンジニアリングチェック、リリース前チェック、および運用保守チェックに使用されます。

目標は「単に動くこと」ではなく、以下を確保することです：

1. アカウントの有効性
2. 権限の充足
3. OpenD の正常動作
4. DryRun / Live セマンティクスの明確化
5. 取引およびデータリスクの制御可能性

## 2. アカウントの準備 (Account Readiness)

リリース前に必ず以下を確認してください：

1. 対応する取引市場のアカウントが開設済みであること
2. moomoo アプリ / OpenD アカウントで正常にログインできること
3. アカウントの必要なすべての規約同意が完了していること
4. アカウント ID が OpenAPI で利用可能であることが確認されていること

確認すべき具体的な項目：

1. `acc_id`
2. 対象市場の取引権限が開設されているか
3. アカウントが証券総合アカウントであるか
4. シミュレーション（デモ）アカウントかリアルアカウントかの区別

## 3. 環境の準備 (Environment Readiness)

以下を必ず確認してください：

1. OpenD がインストールされていること
2. OpenD が実行中であること
3. OpenD のバージョンが利用可能であること
4. ホストとポートの疎通が取れること
5. ネットワーク環境が OpenD との接続維持を許可していること

設定項目のチェック：

1. `futu.opend_ip`
2. `futu.opend_port`
3. `futu.trd_env`
4. `futu.market`
5. `FUTU_ACC_ID`
6. `FUTU_UNLOCK_PASSWORD_MD5`

## 4. 市場範囲のチェック (Market Scope Check)

今回のサポート対象となる市場範囲を明確にする必要があります。

現在の Sentinel は以下の基準で実行されます：

1. 米国株：サポート
2. 米国株 ETF：サポート
3. 米国株オプション：戦略および実行チェーンが明示的にサポートされた場合のみ有効化可能
4. 日本株：現時点では自動取引の対象外

## 5. 相場権限のチェック (Quote Authority Check)

以下を必ず確認してください：

1. 現在のウォッチリストに含まれるすべての市場に対して、対応する相場権限があること
2. 将来的に購読/板情報/歩み値を使用する場合、対応する購読権限（Quote Right）が開設されていること
3. 権限が不足している場合、明確なフォールバック戦略（降格戦略）を策定すること

フォールバック戦略の例：

1. 購読に失敗した場合はスナップショット / 日足履歴にフォールバックする
2. 重要なシンボルの権限がない場合は Live モードへの移行を禁止する

## 6. 取引権限のチェック (Trading Authority Check)

以下を必ず确认してください：

1. 対象市場の取引権限があること
2. 現在のアカウントでその商品の取引が許可されていること
3. シミュレーション環境とリアル環境が明確に区別されていること

リリース前に以下を明确にしてください：

1. `trd_env = 1` はシミュレーション（デモ）を表す
2. `trd_env = 0` はリアル取引を表す
3. `trading.enabled = false` の場合、リアル環境での実行を禁止する

## 7. 実行前チェック (Runtime Preflight)

`daemon` または `live` の実行前に、毎回以下を行ってください：

1. OpenD の接続性チェック
2. アカウント資金の照会
3. 取引アンロックのチェック
4. 取引市場とアカウントの一致チェック
5. 現在のモードの確認：
   - `Disabled`
   - `DryRun`
   - `Live`

いずれかの項目が失敗した場合：

1. `run_status` を記録する
2. サイレントに継続してはならない
3. `Live` モードでは直ちに中止しなければならない

## 8. 実行の安全性 (Execution Safety)

以下を必ず確認してください：

1. `ExecutionGate` が有効であること
2. `global_budget` が有効であること
3. `max_daily_budget` が有効であること
4. `buying_power` が有効であること
5. `TradingDisabled` が明確に記録されること

## 9. レート制限とクォータ制御 (Rate Limit and Quota Controls)

以下の各項目を確認してください：

1. 注文頻度が公式の制限を下回っているか
2. ウォッチリストの取得頻度が履歴 K 線の上限に抵触しないか
3. 購読を有効にする場合、クォータ意識（Quota Awareness）があるか

現在の推奨事項：

1. 日次/低頻度の取引モードを維持する
2. 現在のバージョンに高頻度取引を導入しない
3. 一括注文を導入する場合、まず統一されたレートリミッターを追加する

## 10. ブローカーとの照合 (Broker Reconciliation)

リリース前に少なくとも以下を明確にしてください：

1. ローカルの `ledger` は最終的な権威ソースではない
2. 資金のスナップショットはブローカーから取得する
3. 今后追加すべき事項：
   - 注文状態の照会
   - ブローカー側のポジション照会
   - 約定と持分（ポジション）の照合

## 11. ログと監査 (Logging and Audit)

以下のファイルが継続的に利用可能であることを確保してください：

1. `execution_gate_log.jsonl`
2. `run_status_YYYY-MM-DD.json`
3. `account_snapshot_YYYY-MM-DD.json`
4. `portfolio_snapshot_YYYY-MM-DD.json`
5. `ledger.csv`

moomoo/OpenD 接続における最低限の検収要件は以下の通りです：

1. すべての取引試行に監査記録があること
2. すべての失敗に構造化された理由があること
3. Live モードでの失敗は、ワークフローまたはローカルタスクを異常終了させること

## 12. Go / No-Go 判断 (Go / No-Go Decision)

### Go

DryRun / Live に移行可能な条件：

1. アカウントが開設済み
2. OpenD が接続されている
3. 資金照会が成功
4. アンロックロジックが正常
5. 対象市場がサポートされている
6. ウォッチリストの権限が充足
7. 監査ログおよび `run_status` が正常に出力されている

### No-Go

以下のいずれか一つでも該当する場合、Live モードに移行してはならない：

1. OpenD が不安定
2. `get_funds()` が失敗
3. 取引市場の権限が不明確
4. 対象商品が現在の製品境界外である
5. ワークフロー / 監査ログ / `run_status` が不完全
6. シミュレーションかリアルかの区別が確認できない

## 13. 現在の Sentinel の位置付け (Current Sentinel Positioning)

現バージョンにおける Sentinel の moomoo/OpenD への対応状況は以下の通りです：

1. 米国株の日次観測および実行のメインパスを接続済み
2. DryRun および Live の基本モードを接続済み
3. カウンター（取引所側）からのリアルタイム持分取得による自動照合を完了
4. 注文ライフサイクルの全自動照会およびキャンセル確認を完了
5. リアルタイム購読（Qot_Sub）およびミリ秒単位の実行フローは未完了
