# 2026-11-04 試用篩查の後続作業

2026-10-27 から 2026-11-03 の 6 取引日レポートを根拠にした開発指示のうち、公表契約に入る項目は `trial-followup-publication-20261104` で表示を直す。決算カレンダーと既知供給イベントのバックテストは、この作業の範囲外である。

終了条件は `develop` へのマージではない。対象変更が `main` へ同期されて初めて、その作業は終わる。

修復の受入前は、本システムの出力（REDUCE 一覧を含む）を建玉判断に入れない。`decision_weight = 0`、Probe の有効性と過去 PARTIAL の自己開示、RS 層が前日判断の反転をそのまま記帳する挙動、観測点が 7 未満のとき 7 日結論を出さない挙動は、後続の改版で弱めない。

## 着手済み：資本吸収センサーの公表止血

既知供給イベント一覧との照合が受入を通過するまで、センサーレポートは網羅完了を主張せず、実供給件数の 0 を出さない。金額のない Reported 項目は、精確な件数にしない。EDGAR、8-K、424B、TDnet、および 2026-10-27 から 11-03 の 4 件バックテストは別作業である。

主レポートの Supply Phase も、既知イベント一覧が未受入のあいだはソース成功を網羅完了にしない。`source_health` は `SUCCEEDED` にせず、段階値は `IDLE` にしない。観測した圧力 `LOW` / `NORMAL` / `HIGH` はそのまま残し、変更ログが圧力上昇と誤記しないようにする。一覧の受入と 4 件バックテストは後続 8 のまま未了である。

## 後続 1：Leader Absence から日数を外す

採用するのは日数カウンタではない。リーダー不在の二値と、データが許す最早の立証可能日だけを出す。表示形は「少なくとも <最早の立証可能日> からリーダー不在（立証可能）」。日数は出さない。

履歴が機能有効化前に無く、canonical な履歴が 2026-10-01 からしかないため、固定基線のカウンタは今の不在期間を再構成するしかない。版を付けても、偽の精度が残る。

受入：連続するレポートで日数欄が復活しない。最早の立証可能日は、版付きの基線変更を明示しない限りずれない。日次レポートと週次レビューの本文は、この形に合わせた。

## 後続 2：ブレイクアウト候補の年齢と RS の矛盾

候補年齢はイベント時刻から増やす。テンプレートに固定した「1 日目、準備強度 100」を繰り返さない。ブレイクアウト塊は RS 層の当日状態を使い、方向が衝突した日は既存の `SIGNAL_CONFLICT` を付けるか、萌芽の表示を止める。前日文案の逐語反復は不可。

受入：同一候補が続く日は、年齢が 1 日ずつ増える。RS が反転した当日、ブレイクアウト塊に衝突印か状態変更が出る。萌芽または確認済みで、当日 RS が Weakening のとき、状態ラベルへ `SIGNAL_CONFLICT` を付ける。

## 後続 3：層のあいだの衝突を隠さない

同一銘柄で任意の二層が逆方向のとき、その銘柄の箇所に衝突を明示する。既存の `SIGNAL_CONFLICT` を層の組合せへ広げる。バリュエーションが強気、トレンドが弱気の GOOG 型標本で、レポートに衝突印が出ることを受入とする。構築した標本は `GOOG · SIGNAL_CONFLICT` を返す。日次レポートがライブの評価層とトレンド層を同じ銘柄行へ結合する経路は、決定パケットに評価層が無いため、この作業ではまだ接続していない。

## 後続 4：観察プールの決算

観察プール銘柄の決算は、当日と直前の平日を Finnhub earnings calendar から残す。決算日の翌平日レポートは、その銘柄の EPS と売上の予想・実績を観察として持つ。取引所休日の専用カレンダーは使わない。週末を挟む月曜は直前の金曜を見る。

Corporate coverage が `UNAVAILABLE` で、主条目が地政ヘッドラインのとき、解釈層の主文脈は地政タイトルを出さない。表示は zh `无主上下文`、en `No primary context`、ja `主文脈なし` である。会社カバレッジが使えるときの地政タイトルは、この置換をしない。

受入の最初の点は FIG の 2026-11-04 決算である。市場日 2026-11-05 のパーサ観察に、EPS 予想と実績が残ることをフィクスチャで確認する。現場の 2026-11-05 レポート生成は、この作業の範囲外である。

## 後続 5：AMZN を観察プールへ入れる

観察プールは 10 銘柄から 11 銘柄にする。仮説層が利益プールの移行先として名指しする AMZN を外すのではなく、観測ブロックを足す。受益者一覧に出る銘柄は、観察プールの観測ブロックと一対一で対応する。`config.toml` の有効 watchlist に AMZN を加えた。`trade_enabled` は false のままである。

## 後続 6：REDUCE の理由を銘柄ごとにする

トリガー理由は銘柄固有の数値と閾値を持つ。それが書けない間は、理由なしの状態一覧に下げる。「已掉出核心区超过 3 个交易日」を全銘柄で繰り返さない。共有文案は空にし、空の理由行は出さない。

## 後続 7：数値アンカーのない Gravity

数値アンカーが無い、または信頼度の自己評価が極低のとき、Gravity は `UNAVAILABLE` とする。割安・割高の方向語は出さない。極低は方向語を出さず `UNAVAILABLE` にする。

## 後続 8：既知供給イベントの照合とバックテスト

止血の次に、カバレッジを既知イベント一覧との照合で計算する。データ源は Finnhub ニュースから発行文書（8-K、424B、TDnet 相当）へ広げる。2026-10-27 から 11-03 の窓で、Meta の最大 950 億ドル株式調達計画、Amazon の 481 億ドル長期債務、Microsoft の 250 億ドル超の債券、Oracle の 200 億ドルの株式・債券発行のうち、少なくとも 3 件を金額の桁が合う形で記録する。満たせない間は、実供給を `UNAVAILABLE` のままにする。
